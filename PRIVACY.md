# Olanga Privacy Notice

Last updated: October 19, 2026

This notice explains how the Windows desktop app in the [Olanga repository](https://github.com/firestar3/Olanga-Desktop-Agent) handles your information. It covers the app and its bundled companions. Services you connect, websites you open and your operating system have their own policies. This revision describes current repository source; published builds may differ. See the [release notes](docs/releases/1.6.0.md) for the published 1.6.0 changes.

## At a glance

- Wake-word detection runs on your computer. Idle microphone audio is not streamed to an AI provider.
- Cloud features send the information needed for the feature to the provider you configure. This can include speech, text, conversation context and explicitly shared screen images.
- Conversational learning is on by default. Local rules can save seven supported categories of details you tell Olanga directly; you can pause learning, inspect saved details or undo a recent learned change. This is local memory storage, not model training.
- Saved API keys use Windows-backed encryption. Most other saved content is local but is not encrypted by Olanga.
- Olanga has no developer-operated account service, advertising SDK, automatic analytics upload or automatic crash-report upload. Optional performance measurements stay on your computer unless you export and share them.

## When information leaves your computer

| Feature | Information shared and destination |
| --- | --- |
| Gemini speech and answers | With cloud recognition selected, audio captured for an activated request goes to Google Gemini. Model-routed typed or reviewed transcripts go as text. Requests may also include recent conversation, current checklist entries, saved location and local time, relevant enabled memories, your conversation style and preferred form of address, and a previous screen diagnosis when relevant to the conversation. |
| On-device speech | The bundled Vosk recognizer transcribes audio locally. You review the transcript before sending it. Supported commands can run locally; questions or unsupported requests can still send the reviewed text and context to Gemini. Choosing on-device recognition does not make every feature offline. |
| Screen assistance | Selected-area diagnosis sends the image you select to Gemini. Desktop tasks send a primary-display screenshot, the task, visible window names and related screen information for diagnosis and planning. Approved edits include a new screenshot for verification. The selected edit region limits input actions; it does not crop the primary-display image shared for a desktop task. |
| Notes, projects and selected content | Asking Notes AI shares the current note, its title, your question and recent Notes AI conversation. Project search stays local; choosing **Ask Gemini about these sources** rechecks the reviewed excerpts and sends them, their relative source paths and your question. Changed excerpts require a new search and review. Asking about selected content sends the text you review. |
| Calendar preparation | Calendar import stays local. Asking Gemini to prepare for a selected event sends its title, time, location and description. |
| Current information and news | Google Search grounding through Gemini uses your question and relevant context. Opening or refreshing News sends topic and location queries to Google News RSS; it does not automatically ask Gemini to summarize them. Submitting a News AI question sends the loaded headlines, publishers, dates, links, feed excerpts, saved location and recent News AI conversation to Gemini. Opening a source article contacts its website through your browser. Briefings may request weather and headlines; scheduled online briefing additions have a separate opt-in. |
| Spoken replies | The Windows voice uses the system speech service. If you select NVIDIA Magpie, response text and voice settings go to NVIDIA for speech generation using your NVIDIA key. The explicit reply sample uses that same selected voice and sends its fixed sample text to NVIDIA when Magpie is selected. Short generated replies may be cached in memory. |
| Guided microphone check | The explicit five-second “Olanga audio check” uses the already enabled microphone and local recognizer. It does not upload the check audio or run an assistant command. Opening setup or refreshing the device list does not enable voice input. |
| Gemini Live conversation | Starting this optional mode sends microphone audio continuously during that session, including sounds picked up between turns. Stopping, muting, losing the microphone or closing Work tools ends the session. It has a ten-minute limit. |
| Local model and speech servers | Explicit local questions or answer text go to the loopback server you configure on this computer. Olanga restricts these endpoints to loopback addresses; the server's own storage and network behavior is outside Olanga's control. |
| MCP connections | Connecting contacts the HTTPS server you specify to initialize it and retrieve its tools. Each approved tool call sends its exact reviewed arguments and optional bearer token to that server. |
| Updates and external links | Checking for updates contacts GitHub. Downloading retrieves the installer and verification files from GitHub release services. Opening a link contacts its destination through your browser. Update checks, downloads and installation are manual. |

Internet services receive ordinary connection information, such as your IP address. When a Gemini key is configured, Olanga may open a connection while you begin speaking or typing to reduce waiting time. That preparation request contains no API key, prompt or audio, but it still contacts Google. Configured Magpie voice discovery and testing also contact NVIDIA. The app's font and interface assets are bundled locally.

An activated voice request can follow a wake phrase, push-to-talk or a follow-up listening window. A false wake can activate recording, so watch the listening indicator and mute the microphone when you do not want voice input. Hiding the window leaves Olanga running in the tray; it does not stop listening.

## What Olanga keeps locally

The normal Windows profile is `%APPDATA%\olanga-control`. Development builds or custom launch options can use a different location.

| Data | Storage and retention |
| --- | --- |
| Gemini and NVIDIA keys | Saved in `secure-store.json` using Electron's Windows-backed credential encryption. The app must decrypt them to use your providers. Settings also have an encrypted backup, but several preferences have ordinary local-storage copies. |
| Preferences and personal content | Appearance, conversation style, preferred form of address, microphone device selection, location, wake phrases, News topics and display choices, current notes, checklist entries, timers, reminders, alarms, saved names, routines and schedules remain in the local profile until you change or remove them. These records are not encrypted by Olanga. |
| Explicit and conversational memories | Up to 50 memories share one local list. Conversational records include a category, source label and timestamps; supported categories are name, city, temperature units, measurement units, answer length, favorite color and music genre. Learned details remain until changed, deleted or replaced; they do not expire with the conversation. Automatic learning does not overwrite an explicitly saved memory without a separate confirmation. Answer context selects up to eight relevant enabled memories within 1,800 characters. Up to ten learned-change undo records stay in memory for ten minutes in the current session; their expiry does not delete saved memories. |
| Note versions and deleted notes | Local history keeps up to 15 versions per note, 80 versions overall and 30 deleted notes within a 500,000-character serialized history budget. Typing changes are grouped into 30-second checkpoints. The oldest retained copies leave as these limits fill; they have no separate age-based expiry. Deleting a current note can retain it in Deleted notes. Versions and deleted copies can be removed individually. A separate original-note recovery copy remains until you delete it; another recovery cannot silently replace a different retained original. |
| Conversation and media | Recent assistant conversation, request audio, screen captures, plans and generated speech are held in memory, not saved as an Olanga chat or recording archive. Normal conversation context is bounded to 24 recent messages and 24,000 characters, and is discarded when next checked after 30 minutes of inactivity or on app exit. The last result is also retained in memory for spoken repetition until replaced or the app exits; review of its confirmed unfinished steps is limited to five minutes. A temporary text-edit undo checkpoint lasts up to five minutes. Windows Snipping Tool may separately save captures or place them in clipboard history under your Windows settings. |
| News reading state | Read markers store a hashed story identifier and timestamp, not an article archive. The hash is not encryption or a guarantee of anonymity. Olanga uses at most 250 markers from the last 30 days; older markers are ignored when read and removed from storage on the next marker write or when you clear reading history. Loaded feed content and News AI conversation stay in memory. Feed content is normally reused for up to 15 minutes; a failed refresh can leave older headlines available until replaced or the app exits. |
| Personal backup and restore | Export files can contain any of six selected collections: current notes; checklist; timers, reminders and alarms; schedule definitions; portable appearance and conversation preferences; and Workspace memories, saved names and routine definitions. Files are limited to 4 MB. Saved provider credentials, microphone and other device settings, project-folder registrations, named workspace bundles, window/companion sessions, activity, run receipts, note versions and deleted-note history are excluded. Files are not uploaded or encrypted by Olanga. Private information you wrote into selected notes or memories remains in that content. Files remain wherever you save them. |
| Pre-restore recovery | Before replacing selected personal collections, Olanga saves and verifies their original data locally. This can include earlier note text and note history, memories or task descriptions. The latest copy remains until deleted or replaced by a later eligible restore; an unfinished recovery cannot be silently overwritten by another unrelated restore. Review, download and deletion controls are available in the personal backup center. |
| Workspace-specific backups and recovery | The original Workspace export remains a narrower file containing explicit and learned memories, saved app/playlist names and routine definitions. A separate Workspace recovery copy preserves the original complete Workspace storage record, including any old memories, routine commands, activity metadata, timing measurements and routine run records. These recovery copies have no automatic expiry and remain until you delete them. Downloaded copies remain wherever you save them. Neither export nor recovery copies are encrypted by Olanga. |
| Activity and performance | Keeping activity after restart and collecting local performance measurements are off by default. Saved activity keeps up to 40 receipts with operation types and statuses, without request text or detailed results. Measurements keep up to 200 timing/outcome entries. Routines separately retain up to 10 run records. |
| Named workspaces | Up to 20 named setups and 20 resume records stay in local storage. Setups contain existing component IDs and names; resume records contain component names, step states and result messages. They do not copy project text, credentials or reusable window handles. These records have no automatic age expiry. Remove saved setups or clear run history separately. |
| Work tools | Saved project folders, window sessions and file-operation receipts use local JSON files. Up to 12 project folder records remain until removed; bounded text indexes stay in memory. Up to 30 window sessions can retain app identities, window titles and layouts, with up to 12 windows each. File receipts retain source/destination paths and verification metadata, up to 30 receipts. Up to 20 companion sessions can retain tab URLs/titles or document paths, with at most 30 tabs or 20 documents per session. Imported calendar snapshots stay in memory. Up to 40 schedule definitions and 60 notification-history entries stay locally; history can include reminder text and briefing results. |
| Audio setup results | The chosen microphone device ID is saved as a preference. Input levels, a short recognized check phrase, device label and check timestamps/results stay in memory for the current session. Reply-sample status and selected voice engine also stay in memory. The app does not save a recording archive for these checks, and a completed playback result does not establish that a person heard sound. |
| Connections and downloads | MCP tokens and companion pairing credentials stay in memory. Phone pairing uses a temporary HTTPS session with an essential session cookie on the phone. Downloaded installers, verification metadata and installation results can remain in the local update cache. Exported files stay wherever you save them. |

Local content is accessible to software or people with sufficient access to your Windows account or computer. Windows encryption of API keys does not encrypt notes, memories, exported files or the whole profile. Backups and system-managed caches may retain additional copies.

## Conversational learning

Learning runs locally on clear, direct statements in submitted user text or recognized requests. It uses a narrow rule set, not a model call. Question text, quotations, reported speech, uncertain wording, sensitive categories and operational instructions are excluded by those rules. A clear supported fact in a separate sentence before an information question can be learned; the question itself is not a memory candidate. AI replies, source documents, screenshots and tool output are not inputs to the learning function. The rules are deliberately limited; review the visible learned-memory notice and saved list rather than treating this as a general-purpose personal profile.

**Learn useful details from our conversations** is on by default, independently of **Use my memories in answers**. Pausing learning stops new conversational updates but keeps existing memories and their current answer-use setting. Disabling memory use stops their inclusion as saved-memory context in future answers. An explicitly requested memory can still contain private information, so only save details you intend to keep. Saved facts and preferences never authorize actions or change app permissions. Narrow questions about a single unambiguous enabled fact can answer locally without an answer-provider request; cloud voice input still requires transcription. Other answers and searches select a bounded relevant set of enabled memories. Unrelated general questions omit checklist context, while checklist requests receive a bounded selection with counts for omitted items.

## Your controls

- **Microphone and voice:** use the microphone mute button to stop voice input, or choose on-device recognition in Core settings. Use the separate voice mute button or Windows voice to avoid Magpie speech requests. Quit from the tray to exit the app fully.
- **Provider keys:** remove saved Gemini keys in Core settings. To remove the NVIDIA key, clear its field and save. This removes Olanga's saved copy; revoke a key with its provider if you need to invalidate it everywhere.
- **Memories and saved names:** use Workspace to search, inspect their source, edit, delete or disable memories and saved names. Say “stop learning”, “resume learning”, “what have you learned about me?”, “what memories did you use?” or “forget what you just learned”. A learned change has an on-screen Undo and a ten-minute session limit. Automatic learning protects manual memories; replacing one needs your explicit choice. Deleting, disabling or replacing memories removes dependent tracked local conversation entries and cancels a pending reply that uses them. It does not erase provider copies, unrelated content, exports, note history or retained recovery copies.
- **Personal backups:** choose the collections to export, inspect import counts and explicitly confirm which collections to replace. Imported timers remain paused and schedules disabled until you resume them. Imports never execute routines or notifications. The latest pre-restore copy has separate review, download and deletion controls. Exported note content excludes versions/trash, although a local pre-restore copy can retain earlier history.
- **Workspace-specific backups:** use the narrower Workspace export or its recovery controls. Damaged, unreadable or unsupported Workspace storage pauses writes to that record while session-only work remains available. Reset or replacement requires a successfully saved and verified recovery copy. A recovery reset affects Workspace memories, saved names, routines, activity, diagnostics, run records and Workspace preferences; it does not reset keys, appearance, timers, notes, checklist entries or schedules. Download or delete retained recovery copies separately in Backups.
- **News:** choose topics, story count and unread-only view; mark stories read or unread, or clear reading history. These controls do not delete history kept by your browser or providers.
- **Activity and diagnostics:** use Workspace to clear history or measurements. Turning off performance collection deletes its saved measurements. Exports are created only when you request them and are not uploaded by Olanga.
- **Work tools:** forget a project, remove a named workspace or saved session, clear workspace resume history, remove a schedule, clear the calendar snapshot, or clear notification history from the corresponding panel. Forgetting a project does not delete the source files. Disconnect MCP or companions and stop phone access when finished.
- **Notes:** use Notepad → History to inspect or restore a version, recover a deleted note or delete retained copies. Deleting a current note is not the same as deleting its retained history/trash or a recovery copy. Download or delete original-note recovery copies separately.
- **Audio and Health:** choose a microphone or run a local phrase check and reply sample explicitly in Core settings. Health opens the relevant settings or recovery control; its status check does not test a provider. A separate Gemini connection test sends a short request.
- **Other content:** delete checklist entries, timers and routines with their own controls. Clear location fields to stop including saved location in future requests. There is no automatic expiry for every type of saved content and no single in-app button that erases every profile file.

To remove the entire local profile, first quit Olanga from the tray, save any content you want to keep elsewhere, then remove the specific `olanga-control` folder described above. This also removes credentials, preferences, saved content, operation recovery history and downloaded updates. Do not assume uninstalling removes this profile. It does not remove original project files, your exports, companion-app data, Windows clipboard history, backups or information already sent to providers. File deletion is not a guarantee of forensic erasure.

## Provider policies and retention

Your configured providers process requests under their own terms, account settings and retention policies. Olanga does not control their storage, processing locations or deletion procedures. Use their account/privacy tools for requests concerning information they hold.

Review the terms and privacy settings that apply to your configured service and account before sending private information. Olanga's local memory feature does not determine whether a provider retains or uses requests. [Gemini API terms](https://ai.google.dev/gemini-api/terms) · [Google Privacy Policy](https://policies.google.com/privacy).

For other configured services, see [NVIDIA's Privacy Policy](https://www.nvidia.com/en-us/about-nvidia/privacy-policy/) and [GitHub's Privacy Statement](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement). An MCP service, browser destination or locally installed server may have additional policies of its own.

## Questions and changes

For questions about this notice or the app's behavior, use the [project issue tracker](https://github.com/firestar3/Olanga-Desktop-Agent/issues). Issues are public: do not post API keys, personal recordings, private screenshots or profile files. The maintainer cannot inspect or delete data that exists only on your computer or in your provider account.
